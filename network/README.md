# CROSSFORT 通信対戦

CPU戦、1台の VS PLAYER (`local`)、シーズン1には従来の処理を使用し、通信対戦だけを `lan` モードで動かす。

## 対戦の始め方

1. 2台で同じ公開版を開き、ホームの「通信対戦」を選ぶ。
2. それぞれ自分の保存済みデッキを選択する。40枚、1〜2色、同名4枚までをホストでも検証する。保存済みデッキがない場合は合法な基本デッキも選べる。
3. ホストが「部屋を作成」。相手は14文字のコードを入力するか、表示されたQRを読み取る。
4. 接続表示を確認し、両者が「準備完了」を押す。先攻をランダムに決定して開始する。

PCの起動は不要。部屋コード方式の接続確立にはインターネットを使用する。同じWi-Fiでも端末間通信を禁止するゲストネットワーク等では直接接続できないことがある。Safari/ChromeのWebRTCを使用し、アプリのインストールは不要。実機のiPhone/Androidによる相互接続は未検証。

## 通信と状態管理

- **PeerJS 1.5.5 / WebRTC DataChannel**。ゲームメッセージはJSON文字列をBinaryPackで分割・再構成して送る。通常はPeerServer Cloudで部屋IDとSDP/ICEを交換する。ゲームデータはDataChannelで送る。PeerJS既定のSTUN/TURNを使用し、直接接続できない環境では暗号化された通信がTURNを経由する場合がある。
- ホストの非表示・同一オリジンiframeだけで既存の `startGame/playSelectedCard/attack/endTurn/triggerCard/executeActions` を実行する。ゲストでルールを再計算しないため、乱数結果もホストに統一される。CPUの判断処理は変更しない。
- ホスト自身の表示にも、ゲストの表示にも、明示的な許可リストから作成した観測状態を使用する。各端末では自分を下、相手を上に写像する。レーン番号は共通の戦闘レーン番号を維持する。
- 対戦ID、参加者ID、連番、状態バージョン、選択リクエストIDを検証。古い盤面の操作、手札偽造、資源不足、不正レーン、権限のない選択、重複入力を拒否する。
- 効果の対象、配置先、墓地・手札の選択、探査、発見、相手ターンの報復は、元の選択処理を停止させたまま、選択権を持つ端末へ転送する。入力後に同じ処理を継続する。
- 既存のドロー・配置・攻撃・スペル・数値・破壊演出を利用する。新しい攻撃確認UIや効果連鎖のルールは追加しない。

## 非公開情報と限界

| 情報 | ゲストへ送る範囲 |
| --- | --- |
| ゲストの手札 | ゲスト本人のカード内容 |
| ホストの手札 | 枚数だけ（カード名・IDなし） |
| 双方の山札 | 枚数だけ。本人の山札順も送らない |
| 盤面・LIFE・資源・防衛線・墓地 | 双方の公開情報 |
| 非公開カードの効果選択 | その選択を行う本人だけ |
| デッキ登録 | ゲストの選択デッキをホストへ一度送る。相手用の画面には表示しない |

**ホストは全デッキ、全手札、山札順を保持する。ホストの開発者ツールからの解析・改ざんには耐えない。** 画面の秘匿とゲストへの情報削減は行うが、公平な不正対策を保証するサーバー権威方式ではない。シグナリング事業者には接続メタデータ/SDPが渡る。部屋コードは参加情報なので公開しない。

## 切断と復帰

2秒ごとのハートビートを使用し、10秒応答がなければ切断と判定。操作を無効化し、ルール処理の非同期境界で進行を停止する。120秒以内の再接続に対応し、期限を過ぎると安全に終了する。再試行やhello/welcomeだけでは期限をリセットしない。本人用盤面の反映・現在接続に対応する確認応答・5秒の安定通信を確認してから、ホストが明示的に再開する。盤面同期を待っている間も期限の判定を続ける。

再接続トークンと観測状態はタブの `sessionStorage` に保存する。ホストは加えて確定状態、乱数状態、カードID採番、選択ID採番、処理中の操作と受理済み選択履歴を保存する。リロード時は確定状態から処理中操作を再現し、未解決の選択で待機する。JavaScriptのPromiseやコールバックは保存しない。本人の手札と現在の選択は本人用の状態から復元する。

タブを閉じた後の新しいタブ、保存領域の消去、ホスト交代には非対応。OSが両端末を停止している間もバックグラウンド実行は保証されない。復帰時に保存済み時刻から期限を確認する。画面ロックが120秒を超えた場合は終了する。保存できない環境では再接続を保証できず、エラーを表示する。

## インターネットなしの接続情報交換

「接続情報交換（オフライン）」では、外部ICEサーバーを使わず、収集済みのSDPを圧縮してQR/コード化する。

1. 両端末で事前にページと素材を読み込んでおく。
2. ホストが作成した接続情報をゲストが読み込む。
3. ゲストに表示された返答をホストが読み込む。
4. 接続後、両者が準備完了にする。

接続候補を収集できないブラウザ、AP分離、mDNS/UDPを遮断するネットワークでは利用できない。切断後はホストの「再接続」で新しい情報を作り、再交換する。ページのオフライン起動を保証するPWA/サービスワーカーは追加していないため、**完全オフラインの初回起動には非対応**。大きすぎるQRはコード共有へ切り替える。

## 自前のシグナリングを使う場合

通常は追加デプロイ不要。任意のHTTPSコンテナホストへ `network/signaling/` の最小PeerServerを配置できる。GitHub Pages自体ではNodeサーバーを実行できない。

```sh
cd network/signaling
npm ci --ignore-scripts
PROXIED=true PORT=9000 npm start
```

または同ディレクトリのDockerfileを使用。TLS終端とWebSocket Upgradeに対応するHTTPSリバースプロキシの背後へ置き、`network/config.example.js` を参考に `network/config.js` のホスト名等を設定する。部屋一覧APIは無効。サーバーはゲームの権威処理やデッキ保存を行わない。独自TURNを使う場合、長期秘密鍵を静的な公開ファイルに記載しない。この自前サーバーは今回外部サービスへデプロイしていない。

公式資料: [PeerServer](https://peerjs.com/server/getting-started)、[PeerJS API](https://peerjs.com/client/api/peer)。依存バージョンとライセンスはpackage-lockと `vendor/rtc.js.LEGAL.txt` に記録する。

## ファイルと保守

| ファイル | 役割 |
| --- | --- |
| `core.js` | デッキ検証、観測状態、操作番号、選択入力の検証 |
| `engine.js` | 既存ゲームのホスト用アダプター、選択と復帰 |
| `session.js` | 権威セッション、確定状態と操作履歴 |
| `transport.js` | PeerJS/手動WebRTC、接続情報の圧縮 |
| `lan.js`, `lan.css` | ホーム導線、部屋画面、通信操作と既存戦闘UIの接続 |
| `config.js` | シグナリング設定（既定はCloud） |
| `version.js`, `build-vendor.mjs`, `vendor/` | 互換性識別子と固定依存のビルド |
| `tests/lan-*.cjs` | 同期・秘匿・復帰・ゲーム完走・QR等のテスト |

```sh
npm ci --ignore-scripts
npm run build:network
npm run test:network
```

ゲーム本体、カードDB、ルール、通信処理を変更したら `build:network` を再実行する。両端末のビルド識別子が異なる場合は接続を拒否する。Pagesワークフローにもビルドとテストを追加し、rootの通信素材を既存の `/hex/` とともに配信する。シグナリングのサーバー側コードやnode_modulesは配信しない。

## 検証記録

- 通信追加テスト24件: 合格。元のカードエンジンでLIFE決着までの2参加者シミュレーション、観測状態の秘匿、重複操作、相手ターン報復、対象選択、追加ターン、処理中選択の再現、切断停止、QR画像読み取り等。
- 既存のAI・デッキ編集・配置・月神・シーズンスコア・第三弾青テスト: 合格。
- HEX: lint、型検査、438テスト、build: 合格。
- 既存の防衛線・キーワードHTML・ランドマークの3テストには変更前から失敗があり、同じ失敗を変更前コミットでも確認。今回の修正範囲から除外。
- クラウドブラウザはWebRTCの接続候補を取得できず、実ネットワークのDataChannel確立を確認できていない。部屋の登録・検出までは確認。公開配信しない模擬通信を使い、2画面の準備完了、手札の分離、配置/資源/ターン/攻撃/防衛線の一致、双方のリロード復帰後の操作、安全な退出を確認。
- iPhone同士、iPhone/Android、実機の画面ロック・カメラQR、Wi-Fi間の実測は未実施。これらを確認するまでは実機検証完了とは扱わない。


## 2026-11-24 通信切断・待ち時間の修正

対戦後半のHP7、墓地・ログが増えた状態を使って再現。PeerJS 1.5.5のJSON serializerは16,300 UTF-8バイト以上を送らず `message-too-big` を発生させる。以前のアプリ側上限は文字数300,000だったため、この依存ライブラリの上限を検出できず再接続へ移行していた。HP値による通信制限はない。

- JSONプロトコルを保ったままBinaryPackの自動分割送信を使用。同一の大きな盤面が実際のPeerJS serializer・chunk再構成を通って一致することをテスト。
- 現在の接続用nonceと状態バージョンで盤面反映のACKを確認。同期前はゲームを再開しない。
- 最初の切断時刻を維持し、3秒おきの再接続でも120秒に戻らず期限に達することを、実際のコントローラーの擬似時刻テストで確認。
- ホストのリロード時も、選択待ちの効果を一時停止した状態で復元し、同期後に一度だけ継続する。
- 通信素材のクエリをv2へ変更。更新時は両端末でページを再読み込みし、新しい部屋で開始する。既存の保存済みデッキは変更しない。

今回も実機のSafari/Chromeでの再試験は行っていない。カード効果・CPU評価・対戦ルールは変更していない。
