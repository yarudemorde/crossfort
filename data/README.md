# カード情報の管理

カード追加・修正は次の2ファイルで行います。画面や共通の効果実行処理は index.html にあります。

| ファイル | 内容 |
| --- | --- |
| data/cards.js | CARD_POOLS（色別カード一覧）、CARD_IDS、CARD_SPECIES、CARD_LEGENDARY、CARD_NAME_ALIASES |
| data/card-rules.js | CARD_RULES（各カードの効果定義） |

## カードを追加する

1. cards.js の該当色の CARD_POOLS に [名前, コスト, パワー, 種類, 効果説明] を追加します。説明文の改行は \\n で表します。
2. CARD_IDS に重複しない固定IDを追加します。種族やレジェンダリー指定がある場合は対応する表にも追加します。
3. card-rules.js に同じカード名をキーとして効果を定義します。説明文を書くだけでは効果は実装されません。効果なしのカードに空の定義を追加する必要はありません。
4. 既存の効果タイプを再利用します。新しい仕組みが必要な場合は index.html の共通処理への対応が必要です。
5. 更新したJSの読み込みURLの v を index.html 内で増やします（例: data/cards.js?v=2）。ブラウザに古いカード情報が残るのを防ぎます。JSとHTMLを同じコミットで公開してください。
6. 図鑑・デッキ編集・通常バトル・イベント戦で確認します。

## 互換性と読み込み

- cards.js → card-rules.js → ゲーム本体の順で通常の script タグから読み込みます。async / defer を個別に付けないでください。
- ビルドやJSONの非同期取得は不要です。GitHub Pagesとフォルダ一式を使う構成を維持します。index.html だけを移動せず data と assets も同梱してください。
- 既存の名前・ID・並び順を勝手に変更しないでください。保存済みデッキはカード名を参照します。名称変更時は CARD_NAME_ALIASES に旧名→新名の対応も追加し、関連する表と効果定義を合わせて更新してください。
- スプレッドシートから転記する場合も、更新先はこの2ファイルです。自動同期処理は今回追加していません。
- カード数がさらに増えても、当面はこの構成で管理できます。弾ごとに担当や更新頻度が分かれてきた段階で、弾別の分割を検討してください。
