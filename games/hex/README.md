# CROSSFORT HEX — 機動順ラウンド戦術バトル v2.1

クロスフォート戦記の世界で、固有名を持つ兵士を編成してCPUと戦うブラウザゲームです。公開先は既存の `/crossfort/hex/`。リポジトリルートのカードゲームとは独立しています。

## 開発・検証

Node.js 22以降。

```sh
cd games/hex
npm ci
npm run dev
npm run typecheck
npm run lint
npm test
npm run build
```

`dist/` は静的配信できます。リポジトリのPagesワークフローはルートのカードゲームとHEXを同じ成果物に梱包します。HEXは相対アセットURLを使用します。

## 遊び方

1. 本陣の「出撃」から1〜6名・コスト10以内で編成します。所持兵の確認・名前変更・除隊・補充は「兵舎」で行います。
2. 配置画面のメニューで戦場・サイズ・シードを選びます。実際のマップの金色の6マスへ、下部の兵士をドラッグ、または兵士→配置先のタップで配置・入れ替えます。
3. 機動順に現在の行動兵士が自動選択されます。金色の移動先で経路を確認し、右側の「移動確定」。赤い敵を直接選べば、その場から攻撃できます。
4. 赤い攻撃対象を選び、予測ダメージ・反撃を確認して攻撃します。攻撃せず手番を終えることもできます。
5. 敵本城HP60を削るか敵兵を全滅させると勝利。本城破壊時の降伏兵1名に勧誘を試み、生存味方1名を強化します。戦死した味方は勝利確定時に永久喪失します。
6. 敗北なら戦闘前の配置、またはホームに戻れます。所持キャラクターのレベル・戦績は戦闘前のままです。

マップは1本指・マウスドラッグで移動、2本指ピンチ・ホイールで拡縮できます。パネルの開閉や部隊選択でカメラを自動変更しません。キーボードでは盤面マスをTabで選び、Enter/Spaceで操作できます。

## 機動順・成長・反撃

「移動」は距離、「機動」はラウンド中の行動順です。生存兵士を機動降順に並べ、各1回行動します。同値はシード・ラウンド・安定した個体キーによる決定的な優先度で解決します。待機も1行動。移動確定では順番を進めず、攻撃または行動終了で進めます。

基礎値は騎士HP30/攻撃12/機動10/反撃×1.0、弓兵22/9/12/×0.5、斥候18/6/16/×2.0。本城HP60。反撃は砂漠−1（最低1）→成長後倍率→切上げ→森林/山岳+1の順です。

勝利時の強化でHP+3/4/5、攻撃+0/1/2、機動+0/1、反撃+0.0/0.1を独立・等確率に抽選し、対象と結果を同じIndexedDBトランザクションで保存します。履歴は3回分まで保持し、MAX以後は成長しません。

## スマートフォンUI

戦闘はコンパクトなHUD、可視部隊だけの行動順タイムライン、残り領域のマップ、固定高アクションバーの構造です。タイムラインのタップは詳細確認専用で、行動権は移しません。選択・移動確認・攻撃確認・CPU手番で下部の高さを変えません。ページ全体はスクロールせず、兵士一覧や詳細だけを内部スクロールします。戦況・地形・設定・詳細は初期状態で閉じ、スマホはボトムシート、PCは右側パネルで開きます。Escapeで閉じられます。

盾／弓／短剣のオリジナルSVGとHPバーで職業・陣営を区別します。移動は金、攻撃は赤。予測には与ダメージ・反撃・双方の予測HPを表示します。UIを開いてもカメラはリセットしません。

検証結果・スクリーンショット・再検証手順は [ROUND_SYSTEM_ACCEPTANCE.md](docs/ROUND_SYSTEM_ACCEPTANCE.md) を参照してください。

勝利後の次戦で編成人数だけが6/6に残る問題は修正済みです。戦死・除隊した兵士を編成枠と配置選択から除き、生存者の順序を維持します。原因と回帰検証は [FORMATION_RECOVERY_FIX.md](docs/FORMATION_RECOVERY_FIX.md) を参照してください。

## 保存と旧データ移行

保存レコードはschemaVersion 3です。既存のIndexedDB名・ストアを維持します。v2兵士のID・名前・所属・Lv・個体差・戦績・勧誘/除隊の記録を保持し、Lvに応じた成長履歴をIDから一度だけ生成して保存します。未完了報酬も継続します。旧方式の進行中対戦は原データを`legacyBackupV2`へ退避し、所持兵士を保持したまま編成・配置・マップ・シードを復元して戦闘前へ戻します。移行と退避は単一トランザクションで行い、不正なデータは上書きしません。

IndexedDBに所持データと非公開の戦闘スナップショットを分けて保存します。操作結果は保存成功後に画面へ返します。勝利と報酬開始は同じトランザクションで確定し、リロード後は戦闘または未完了報酬を再開します。複数タブからの同時更新はリビジョン照合で拒否します。

データは使用中のブラウザ・端末・サイトの配信元ごとに保存されます。端末間同期はありません。ブラウザのサイトデータを消去すると所持データも失われます。旧カード版の対戦データを新しいロスターに変換しません。破損セーブは上書きせずエラーにします。

## 構成と暫定項目

- `src/character/`: ロスター、成長、ラウンド順、戦闘、CPU、報酬、移行・検証、保存、Worker、可視演出フレーム
- `src/app/CharacterApp.tsx`: 全画面シェルと情報シート
- `src/app/useCharacterGame.ts`: 共通のWorker通信・画面操作状態
- `src/components/tactics/`: HUD・固定アクションバー・軍営・兵舎・編成・配置・結果のUI部品
- `src/components/character/`: 観測情報だけを描く盤面
- `data/ruleset.characters.json`: 職業、成長、編成、勧誘等の調整値
- `data/presentation.settings.json`: 移動・戦闘演出の時間とカメラ操作
- `docs/GAME_SPEC.md`: v2ルールと確定・暫定の区分

初期名・所属の配分、CPU編成、地形補正、待機、敵全滅勝利、勧誘1回、ローカル保存は仕様書の暫定値です。経験値・スペル・手札・資源・建設・領土収入・ユニーク職・対人戦は使用しません。将来職用の拡張は独立した職業定義を追加して実装できます。

旧カード版のソースとテスト、画像、マップデータは参照用として残しています。旧仕様書は `docs/archive/` に退避しました。旧テストは旧ルールの参照回帰確認であり、v2の受入試験とは分けています。
