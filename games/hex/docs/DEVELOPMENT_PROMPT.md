# 開発エージェント向け実装指示

あなたはTypeScriptでブラウザゲームを実装するゲームエンジニアです。
添付の `docs/GAME_SPEC.md` を**唯一の実装仕様**として、2人対戦形式のうちプレイヤー対CPUモードが遊べる『CROSSFORT 戦記 ― ヘックス領土戦』のプロトタイプを実装してください。

## 要件

1. `GAME_SPEC.md` の **[確定]** ルールは変更しない。
2. **[暫定実装]** の処理は、ゲームを完走できる初期既定値としてそのまま実装し、設定値で変更可能にする。別の方法を採用したら変更点をREADMEとIssueに残す。
3. コアロジックは副作用のない関数で作り、UIコンポーネントがルールを直接改変しない設計にする。
4. デッキ16枚、カード3種類、ターン開始の3枚ドローと2～5枚の資源公開、1回交換、ターン終了時の**回収束だけをシャッフルして山札の下へ戻す**処理を厳密に実装する。
5. 六角座標、6種類の地形補正、移動と攻撃・反撃・累積ダメージを実装する。
6. ユニット・本城・ランドマークの盤上インスタンスとカードの循環を独立させる。
7. ランドマークは配置順で領土を優先し、先行建造物の破壊時には全領土を再計算する。視野と攻撃射程は領土の上書き有無から独立させる。
8. プレイヤー別の探索済み地形を保持し、現在視野外の敵ユニット・施設は見せない。CPUの意思決定にも隠れた敵の情報を渡さない。
9. 16枚の開発用サンプルカード（`data/cards.prototype.json`）と2種類×3サイズの開発用サンプルマップ（中は`data/maps.prototype.json`、小・大は`data/maps.additional.prototype.json`）を使って、ルールを最後までテストできる状態にする。正式なカード名・世界観設定と取り違えない。
10. `docs/ACCEPTANCE_TESTS.md` のテストを追加し、CIで実行する。
11. ダーク中世のCROSSFORTに合わせた操作性の高いUI。ユニットを選ぶ→移動先・攻撃対象を表示→確認して確定、という誤操作しにくい導線を作る。
12. GitHub ActionsからGitHub Pagesへデプロイできる構成を作る。ブラウザ上で対CPU対戦の開始・終了・再戦ができること。

## 推奨開発順

1. 型定義・盤面・状態遷移・デッキ資源・単体テスト
2. 移動、視野、戦闘、ランドマーク領土の計算
3. 戦場画面、カードUI、イベント表示
4. CPUの意思決定、ゲーム終了と再戦
5. CI、デプロイ、PC／スマホ操作検証

## 完成基準

- 仕様書の確定条件を満たし、CPUを相手に敵本城破壊まで遊べる。
- 再現用seedで任意局面をテストできる。
- hidden情報がUIやCPUの選択へ漏れない。
- 不正操作が状態を壊さない。
- READMEとテストを含むGitHubリポジトリとして納品する。

**禁止**：カード効果・領土・攻撃タイミング・勝利条件を独自判断で変更しないこと。未確定の正式カード内容を創作して完成版扱いしないこと。
