# 実装上の解釈と調整箇所

基準は `GAME_SPEC.md` v1.1。2026-11-03の追加承認でマップサイズと資源公開上限5枚を反映し、それ以外の確定ルールは維持しています。以下は仕様書に示された暫定規則と、その実装箇所です。

| 項目 | 初期実装 | 変更箇所 |
| --- | --- | --- |
| 本城/基礎拠点 | 本城12/2/1、別施設の基礎拠点10/1/1 | `data/ruleset.prototype.json`, `data/cards.prototype.json` |
| 本城領土 | 領土1、初期配置番号0、資源には数えない | ruleset, `createGame`, `calculateTerritory` |
| 召喚と循環 | カードとは別の駒を生成。再使用で複数駒 | `playMutable`（applyActionの複製内） |
| 移動地形 | 出発点で一度だけ判定。基本0は0、基本正値は最低1 | `calculateMovement` |
| 移動＋攻撃 | 1つの原子的な`act`に経路と対象IDを含める | `actMutable`, `Action`型 |
| 隠れた敵との遭遇 | 接触マスに入らず手前で停止、行動を消費 | `actMutable` |
| 味方を通過中の遭遇 | 直前が味方ユニットの場合、最後に通った停止可能マスへ戻る | `actMutable`の`lastFree` |
| 砂漠 | 有効戦力-1、最低1。被弾直前の有効戦力以上で死亡 | `calculateEffectivePower`, `damage` |
| 地形反撃 | 森林/山岳だけ反撃ダメージ+1、戦力自体は増えない | ruleset, `combatMutable` |
| 施設の重複 | 全施設を配置順で再計算。視野/射程は独立 | `calculateTerritory`, `stats` |
| 仮スペル | heal/directDamage/reveal/temporaryPowerBonus | cards JSON, `playMutable` |
| reveal | 現在見える地点の周辺地形だけ探索。持続視野なし | `playMutable` |
| 強化の期限 | 自ターン終了時に解除。生存判定も実行 | `recycleMutable` |
| 情報表示 | 現在視野外は地形のみ。敵施設/領土色/敵ピンを非表示 | `getObservation` |
| 山札順 | 自分/相手とも観測へ順番を渡さず枚数だけ表示 | `Observation`型 |
| 同一マスの施設と部隊 | 別インスタンスで同居、対象はIDで選択 | `getLegalActions`, UIの対象一覧 |
| 先後補正 | なし。ユーザーが先攻/後攻を選択 | `createGame`, setup UI |
| CPUの上限 | 評価12,000候補/1ターン120操作 | `data/prototype.tuning.json` |
| CPUの評価 | 勝利/防衛/有利交換/拠点展開/進軍/索敵 | `chooseCpuAction` |

明記されていないケースの扱い：

- 不正な移動後攻撃は経路・探索・イベントも含めて全て取り消します。唯一、隠れた敵への接触は仕様に従って停止する合法な結果です。
- 既に行動した部隊にもスペルは使用できます。行動回数を戻す効果はありません。
- 資源は数値合計で支払い、個別の資源カードを消費しません。
- 自軍に建設した施設の領土・視野は即更新し、公開資源枚数は次の自軍ターンから反映します。
- 相手の資源は合計と残量のみ観測に含めます。相手の手札・使用済み・山札順・現在非表示の行動は公開しません。
- 本城初期座標は公開のため、敵本城が未発見の間も「敵本城 初期地点」の地図記号だけを表示します。現在の本城の戦力・生存状態を示す駒ではありません。

今後の調整候補（今回のブロッカーではありません）：正式カードへの差し替え、CPUの局面評価/勝率調整、先後バランス、正式地名、オンライン用の権威サーバー。仕様書v1.0で将来扱いの項目は追加していません。

## マップサイズと資源上限（2026-11-03）

- 中の地形ファイルはバイト単位で維持。小・大は `maps.additional.prototype.json` に2種類ずつ追加し、左右対称の配置と平原の本城周辺を用意。中央の進軍路は既存の通行可能な地形で構成します。正式な戦場配置ではありません。
- `map-sizes.json` は公開してよいサイズの定義。`maps.catalog.json` は種類ID・サイズ・半径・枚数・本城だけを生成し、hexes/terrainを含みません。
- `GameState.mapId` とWorkerの操作境界は変更せず、種類×サイズの具体IDを使います。中は既存ID、小・大は `-small` / `-large`。再戦・記録も具体IDを保持します。
- カメラの初回/全体表示は公開座標と六角形の外周から計算。UIリサイズはカメラに触れず、ドラッグ・ピンチ・ホイールを維持。
- 資源計算関数は元から設定値を参照しているため、エンジンの式は変更せず publicCardCap だけ5へ。
- 旧完全リプレイ4件は、旧資源上限4・中2マップの設定を明示して従来のSHA256と比較します。現行設定の完全リプレイは全種類・サイズで検証します。
