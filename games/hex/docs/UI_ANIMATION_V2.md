# 戦闘画面 UI・アニメーション v2

2026-11-02。対象は `games/hex/`。手札だけを開閉する構成に整理し、構造化された計算結果から移動・戦闘を描画します。

## UI

- 資源/記録/選択詳細のアコーディオンとPCサイドバーを撤去。収納した領域に空白を残しません。
- 手札は最初は収納。スマホ/PCで共通の開閉状態を使い、カード・部隊・経路の選択を保持します。
- 資源内訳と戦況記録は「対戦メニュー → 対戦情報・記録」で閲覧できます。選択カードのⓘは拡大表示、部隊のⓘは個別確認画面を開きます。データ/既存の記録保存は維持しています。
- 常時表示は手番/ターン、本城の公開戦力、資源、ターン終了、手札、補助地図操作。選択中だけ簡易情報と必要な操作を追加します。

## 計算結果と表示の分離

`src/game/engine.ts` に追加したのは任意の読み取り用記録点です。移動/戦闘/地形/領土/CPUの計算式や判定は変更していません。`GameState`、ゲーム内イベント、操作列、乱数消費も同一です。

`visualTrace.ts` は、各到着、命中量・命中前後の戦力、消滅、探索、配置、更新の構造化データを収集します。記録先へ渡す状態は完全に複製し、記録先の変更/例外が権威状態に影響しないようにしています。元の文章ログは変更せず、演出では解析しません。

Worker内の `visualFrames.ts` が各段階で既存の観測セレクターを呼び、公開済みの `hexes` と `pieces` だけへ変換します。相手の手札・山札・非公開状態は演出フレームに含めません。

- 見えないCPU移動はフレーム0件。
- 視野へ入る敵は到着マスだけで出現。出発地点を送りません。
- 視野から出る敵は最後に見えた場所で消え、視野外の終点を送りません。
- 視野外からの被弾では、攻撃元ID/座標/射程を送りません。
- 不正な操作で途中の記録が発生しても、フレーム全体を破棄します。
- 隠れた敵に阻まれた場合の引き返しも、実際に通った中心を逆順に辿ります。

## 再生順序

`AnimationQueue` は「開始 → 移動/飛翔 → 到着/命中 → 表示保持 → 次イベント」を直列実行します。命中後の保持時間を独立させ、描画の遅延があっても攻撃と反撃を同じ描画へまとめません。

- 移動：1マス210ms＋区切り45ms。アイコンのSVG transformだけを補間。各到着で公開視野と探索を更新します。
- 近接：発光、対象方向への踏み込み、方向線と斬撃。
- 射程2：方向線と飛翔体。到達時に数値/戦力を更新。
- スペル：対象位置の汎用魔法エフェクト。
- 通常ダメージは赤、反撃は橙、回復は緑の＋数値。表示600ms。
- 致死ダメージはまず0を表示し、360msで暗転/縮小/フェード。完了してから除去と領土の更新を反映し、変化した公開領土を強調します。
- 動くアイコンは静止層から除外し、最上層で1つだけ表示します。
- 演出中のゲーム行動は無効。カメラ操作は維持し、戦闘が画面外の場合だけ同じ倍率で必要な距離を移動します。
- 終了時は必ずWorkerの確定観測へ置き換えます。再戦/離脱ではキューを破棄し、リクエストのセッション番号で古い応答も破棄します。

暫定値は `data/presentation.settings.json` に集約。移動時間/区切り/イージング、攻撃/飛翔/数値/消滅、ズーム上下限と速度を変更できます。`prefers-reduced-motion` 時は移動を省略/短縮し、数値を静止表示で残します。

## マップ入力

`useMapGestures` と `MapGestureController` はブラウザのページ拡大とは独立しています。

| 入力 | 動作 |
| --- | --- |
| 1本指/左ボタンの短い操作 | マス選択 |
| 10 CSS px以上のドラッグ | 盤面移動。終了クリックを抑止 |
| 2本指の間隔変化 | 2本指の中心を保持して連続ズーム |
| 2本指の中心移動 | 盤面移動 |
| マップ上のホイール | カーソル位置を固定したズーム。ページへ伝播しない |
| 手札ハンドルの上下操作 | 手札のみ開閉 |

`touch-action: none` と非passiveなwheel listenerはマップ領域だけに適用。ヘッダー、手札、ゲーム外のブラウザ操作には適用しません。SVGカメラのtransformとメモ化した盤面を分離し、ズームでタイル配置を作り直しません。

### 検証範囲の限界

実機iOS/Androidのマルチタッチとノッチ/アドレスバー伸縮は、この環境では直接確認できません。ピンチ/2本指移動は同じ制御クラスの入力列で検証し、PCの実ホイール/ドラッグはブラウザで確認しています。60fpsを目標としたtransform/RAF構造ですが、実機GPUでの性能保証は行っていません。クラウドブラウザは操作間に描画を停止する場合があるため、その環境のフレーム間隔を実機FPSとして報告していません。

## UI操作時の表示位置の修正（2026-11-03）

手札と選択欄の高さ変化に合わせてカメラを半分の差分だけ自動移動していた処理を削除しました。SVGの寸法はCSSピクセルのまま描画し、ResizeObserverとReactの更新間に古いviewBoxが中央揃えされる一瞬のずれも解消。表示領域だけを更新し、手動で決めた位置・倍率を保持します。プログラムによるフォーカスは `preventScroll` を使い、マップ領域は `overflow: clip` で隠れたスクロールを防ぎます。全体表示・自軍位置ボタンと戦闘演出のカメラ追従は維持します。ゲームロジックの変更はありません。

修正前は390×844で手札展開により105px、カード選択により34px移動することを再現。修正後は390×844・844×390・1366×768の開閉/選択/解除で、同一マスの画面座標・カメラ位置・倍率の差が0。カード詳細の開閉でも同一でした。ページとマップ内部のscroll位置も0のままです。記録は `docs/evidence/ui-stability-20261103.json`。UIリサイズ、手動操作後の維持、明示した全体表示/ホイールを確認する回帰テスト3件を加え、全126件成功。実機iOSの確認は未実施です。
