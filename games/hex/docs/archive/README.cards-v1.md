# CROSSFORT 戦記 — ヘックス領土戦

プレイヤー対CPUのブラウザ用戦略カードゲーム。添付DEV PACK v1.0と追加承認を反映した `docs/GAME_SPEC.md` v1.1を基準に実装したプロトタイプです。**ゲーム開始 → 配置・索敵・移動・戦闘 → 本城破壊 → 勝敗 → 再戦**まで遊べます。16枚の仮カード・小37・中61・大91マスの仮マップ2種類を同梱しています。正式カードや新しい世界観設定は追加していません。

## 起動

Node.js 22以降とnpmを用意し、このフォルダで実行します。

```sh
npm ci
npm run dev
```

端末に表示されるローカルURLをブラウザで開いてください。

ビルド済みの `dist/` も同梱しています。Node環境がない場合、Python 3のあるPCなら次のコマンドでも遊べます。

```sh
python -m http.server 8080 --directory dist
```

ブラウザで `http://localhost:8080` を開きます。**index.htmlのダブルクリック（file://）ではWeb Workerを読み込めません。HTTPサーバー経由で起動してください。**

## 操作

1. マップ種類・サイズ（小／中／大、初期は中）・先攻/後攻・乱数シードを選び「戦場へ進む」。デッキ欄を開くと16枚を確認できます。初版のデッキは、添付データの16種各1枚の標準構成です。
2. 手札を選び、光るマスを選択して確認すると配置・使用できます。ユニットは自軍拠点の隣、施設は自軍ユニットの隣に建設します。必要な資源と配置ターンの行動制限を確認画面に表示します。
3. 自軍の駒を選ぶと移動可能範囲を表示します。移動先を選んだ後、敵を選ぶと「移動後に攻撃」を1行動で確定できます。「移動を確定」はその駒の行動を終了します。
4. 同じタイルに施設とユニットがいる場合は、一覧から対象を選択します。攻撃は確認画面で確定するまで実行しません。
5. 手札の交換は1ターン1回。残りの行動がなければ「ターン終了」でCPUへ交代します。
6. 敵本城を破壊すると勝利。結果画面で再戦・戦場選択ができます。再戦ではマップ種類・サイズ・シード・先後を維持し、同じ初期配列になります。

`⚔ 戦力 / ◉ 視野 / ➶ 射程 / ↟ 移動 / ⬡ 領土 / ◆ 資源`。マップはドラッグ・ピンチ・ホイール・＋/−ボタンに対応。サイズごとに全体を初期表示し、UIの開閉で位置・倍率を変えません。施設を選ぶと本来の領土範囲を点線で表示します。

## 固定したルールとデータ

- 本城は戦力12・視野2・射程1。戦力10の基礎拠点は別の建設施設。
- 手札3枚の後に `min(5, 2 + 生存ランドマーク数)` の資源カードを公開。本城は数えません。3基以上で5枚、最大15資源。各カードの💎は1〜3のままです。
- ターン終了時、手札・公開資源・使用済みの**回収束のみ**をシャッフルし、残った山札の下へ連結。盤面の駒は残ります。
- 戦力は受けたダメージ分だけ低下。生存・射程内の防御側が残存戦力で反撃します。
- 森林/山岳は反撃ダメージ+1。移動の補正は出発地点で一度だけ判定。砂漠の致死判定も仕様書に従います。
- 領土は生存する施設の配置順で決定し、破壊時は全領土を再計算。視野と施設の射程は領土取得面積から独立。
- 探索済み地形は永久保存。敵駒・敵施設・現在の領土色は現在視野内だけに表示。双方の探索履歴は独立。

変更するデータの正本は次のファイルです。中サイズの元マップと16種カードは維持。追加承認に従い、資源上限を5へ更新しました。

| ファイル | 内容 |
| --- | --- |
| `data/cards.prototype.json` | 16枚のカード、効果IDと引数、双方のデッキ |
| `data/maps.prototype.json` | 中サイズ2マップの元タイル・地形・本城座標（変更なし） |
| `data/maps.additional.prototype.json` | 小・大サイズの追加4マップ、種類ID、地形、本城座標 |
| `data/map-sizes.json` | サイズ名・半径・枚数・初期サイズ |
| `data/ruleset.prototype.json` | デッキ/資源/本城/地形などのパラメータ |
| `data/prototype.tuning.json` | CPUの評価・行動上限、演出待機時間 |

`npm run data:sync` は地形を含まないマップ一覧を自動生成します。開発・型検査・ビルドの前にも自動実行します。複雑な暫定ルールは個別の純粋関数へ分離しています。採用した解釈と調整箇所は `docs/IMPLEMENTATION_NOTES.md` を参照してください。

## GitHubでの配置と公開

`yarudemorde/crossfort` の `games/hex/` がこのゲームのソース、`hex/` がビルド済みゲームです。既存ゲームはリポジトリのルートにあり、本作は `/crossfort/hex/` から開けます。

```sh
cd games/hex
npm ci
npm run dev
```

ルートの `.github/workflows/hex-ci.yml` が型検査・lint・161件のルール/描画/結合テスト・ビルドを実行します。`pages.yml` は同じ検証後、既存ゲームの `index.html`、CSS、`assets/`、`data/` と本作の最新ビルドを同じPages成果物へまとめて公開します。既存ゲームのソースは変更しません。

GitHub PagesのSourceが未設定の場合は、リポジトリの Settings → Pages → Source で GitHub Actions を選びます。`main` へのpushか、Actionsの「Deploy Crossfort and Hex to Pages」で再公開できます。Viteの相対baseにより、Worker・CSS・JSは `/hex/` のサブパスでも読み込めます。

## スマートフォン・PCでの操作

- 戦闘中に開閉するパネルは手札のみ。初期状態は収納。カード選択後も収納でき、配置候補・部隊・経路の選択は維持します。
- マップは1本指/左ドラッグで移動、2本指のピンチ/ドラッグで拡大・縮小/移動、PCホイールでカーソル位置を中心にズームします。ゲーム領域外のブラウザ操作は制限しません。
- 移動する駒は各マスの中心を順に通り、到着時に探索・視野を更新。近接/射撃/スペル、ダメージと回復、反撃、消滅を盤面上で順番に表示します。
- 選択中のカード/部隊は簡易表示。ⓘでカードの拡大・部隊の確認画面を開けます。資源内訳・記録は対戦メニューの「対戦情報・記録」から確認できます。
- 移動確定・手札交換・ターン終了は従来の確認/実行処理へ接続。演出中は新しい行動をロックし、カメラは操作できます。
- 主要ボタン44px以上、Safe Area、dvh、縦横画面、prefers-reduced-motion、キーボードに対応します。

実装・公開範囲・検証の詳細は [UI_ANIMATION_V2.md](docs/UI_ANIMATION_V2.md) を参照してください。前回の画面再構成記録は [UI_LAYOUT_REWORK.md](docs/UI_LAYOUT_REWORK.md) です。

## 演出の設定と開発用確認

`data/presentation.settings.json` で移動210ms/区切り45ms、イージング、攻撃/飛翔体/数値/消滅、カメラの速度とズーム上下限を調整できます。ルール値とは独立しています。

`npm run dev` 後に `/qa/animation.html` を開くと、確定した固定局面で近接/反撃・射程2・スペル・回復・施設破壊・3マス移動を再生できます。この開発画面はGitHub Pagesの本番ビルドには含まれません。

ゲームエンジンには計算結果を読み取る任意の記録点のみ追加。Workerで各段階の公開盤面へ変換し、権威状態・CPU判断・乱数は変えません。文章の解析によるダメージ推定は行いません。改修前の4対戦と完全な最終状態のSHA256が一致する結合試験を用意しています。

## 構成

```text
src/app/                   React画面 / Workerとのメッセージ境界
src/components/            マップ・カード・駒・ジェスチャーの描画
src/presentation/          表示キュー・演出の型・イージング
qa/                        開発用の固定局面（本番ビルド対象外）
src/game/engine.ts         不変な状態遷移 / 戦闘 / ターン / カード使用
src/game/rules/            六角座標・地形・領土・視野
src/game/selectors/        プレイヤー別の観測 / 観測に基づく合法手
src/game/cpu/              観測だけを入力にするCPU評価
src/game/rng/              シード付き乱数 / シャッフル
src/data/                  地形を含まない画面用カタログ
scripts/                   データ生成
 tests/unit/               ルール・回帰試験
 tests/integration/        CPU完走・再現・Worker境界の試験
.github/workflows/         CI / GitHub Pages
 dist/                     ビルド済み公開物
```

権威状態はWeb Worker内に保持し、React画面へは `Observation` と人間の合法行動だけを送ります。CPUにも専用の観測と公開カード/ルールだけを渡し、未知の地形や非表示の敵を評価しません。これは静的な1人用ゲーム内の情報分離です。配信データや開発者ツールからの解析を防ぐサーバー側の秘匿ではありません。将来オンライン対戦にする場合は、権威状態と対戦相手の秘密をサーバーへ移します。

## 記録と再現

対戦メニューの「対戦記録を保存」は、シード・マップ・先後・受理された人間の操作列と、人間に公開済みのイベントをJSONで保存します。具体的なサイズのマップIDと種類ID・サイズ・半径も保存します。相手の秘密手札、山札順、視野外の行動は含みません。CPUの選択は同じシードと操作順から再生成できます。内部試験用の完全な操作列は `GameState.commands` と `replay(seed, mapId, commands, firstPlayer)` で再現します。Workerにも人間の操作列を再現する `replay` リクエストを用意しています（UIのファイル読み込み機能は初版では提供しません）。

## 初版の範囲

難易度は標準のみ、デッキは添付の1構成です。正式カード/新規固有能力、オンライン対戦、保存・再開、効果音は対象外です。勝率やカード間のバランスは今後の実戦調整が必要です。フォントを取得できない環境では端末の明朝体へフォールバックします。

## 地形アート

提供された平原・森林・山岳・湿地・河川・砂漠・霧の7画像を地形ごとに表示します。画像ファイルは加工せず、六角形の表示領域に合わせてクリップします。未探索マスは実際の地形に関係なく霧画像だけを描画します。対応表は `docs/TERRAIN_ART.md` を参照してください。

## マップサイズと資源公開上限（2026-11-03）

開始時に種類と独立して小37・中61・大91を選べます。初期は中。中の元配置は変更せず、追加サイズは別データです。全体表示はタイルの外周を計算し、UI開閉時はカメラを固定します。資源は `min(5, 2 + 生存ランドマーク数)` 枚、最大15。詳細と検証は [MAP_SIZES_RESOURCES.md](docs/MAP_SIZES_RESOURCES.md)。
